First capture: stock BO3, AAE, Origins, one or two players.

The recorder runs outside BO3. It samples once per second and flushes each row.
Captures stay in research/captures/live/. Git ignores this folder.
Keep all dumps, settings, and raw logs local.

1. Launch stock BO3 through Steam.
2. Load All-around Enhancement and start Origins.
3. For co-op, host the match on this PC.
4. Hold Ctrl+Shift+F6 briefly when the match starts.
5. Hold Ctrl+Shift+F7 briefly before an upgraded War Machine volley.
6. Hold Ctrl+Shift+F8 briefly after the last shot.
7. Keep the match unpaused for at least 25 seconds after a controlled volley. Let projectiles and effects clear.
8. When Connection Interrupted appears, hold Ctrl+Shift+F9 briefly.
9. Keep BO3 open while the snapshot completes. Record the round and exact error text.
10. After the match, hold Ctrl+Shift+F10 briefly to stop recording.

F9 writes a full memory snapshot. This can use several gigabytes of disk space.
A snapshot can briefly pause BO3. Clone mode reduces this pause.
Wait for the dump_completed event before repeating a failure snapshot.
The recorder does not automatically recognize Connection Interrupted.
The immediate failure snapshot can preserve script errors, the saved engine error, and both resource pools for private analysis.
The recorder does not decode these fields. An empty or older error buffer does not identify the failure cause.

To add match details from the repository terminal:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\source\Send-Marker.ps1 -Action match-start -Map Origins -Mode Solo -PlayerCount 1 -HostRole Host

For two players, use -Mode Coop -PlayerCount 2 -HostRole Host.
Use -HostRole Client if someone else hosts. That capture cannot expose their server process.
For a round or error note, use -Action note -Round 40 -Note "Exact message or observation".
For an optional baseline snapshot, use -Action dump -Note "Idle before upgraded War Machine fire".

To start another recorder after the first process exits or recording stops:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\source\Start-Capture.ps1

To install the Microsoft capture tool on another PC:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\source\Install-Tools.ps1

To repeat the E2E verification:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\source\tests\Test-Recorder.ps1
The test produces a report, telemetry, events, and a verified full memory dump.
It uses a disposable target process and does not target BO3.

The recorder waits for BlackOps3.exe and stops when that process exits.
It records process exits, but it cannot guarantee a full dump after the process has exited.
The separate read-only entity sampler is available under source/live/. Read source/live/README.txt for its commands.
It requires a private profile verified against the exact executable. Its native E2E passed, but game sampling remains unvalidated.
Equal repeated reads reject observed changes. They do not produce an atomic game snapshot.
Projectile creation and deletion, server frame time, and GSC script threads still need targeted instrumentation.
OS memory and thread counts alone cannot prove an entity leak.
The beta's grenade scripts use a 20-second notification timeout and a separate three-second dud deletion delay.
Those values do not bound all projectile lifetimes or establish a leak.
Record advancing server time during recovery. A paused solo match does not test cleanup.
For a suspected retained entity, compare the same slot generation, raw cleanup clock, flag, and per-entity frame guard.
A later event can refresh the clock. Advancing server time alone does not prove that entity received its normal frame.
Native deletion queues cleanup of entity-owned script notification waiters. Normal VM work drains this queue.
To test failed cleanup, follow the same entity generation after delete and after the queue drains.
The script-variable pools are separate from the entity pool. Threads share script-variable slots with other values.
Function call depth and OS thread counts do not count all suspended script threads.
No root cause or fix is confirmed yet.
