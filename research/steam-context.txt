Child-only Steam identity environment checkpoint

SteamContext.h/cpp returns a Unicode environment block for CreateProcessW with
CREATE_UNICODE_ENVIRONMENT. It snapshots GetEnvironmentStringsW, preserves every
unrelated entry and hidden drive-current-directory variable, and replaces only
SteamAppId and SteamGameId with 311210. It does not modify its parent's environment.
The caller retains the vector through process creation. No file or launch-option change is needed.

Failures.txt declared four focused groups before implementation.
The owned child E2E passed with the real inherited parent and a synthetic parent.
The synthetic parent contains mixed-case wrong Steam IDs, a Unicode value and =C:.
The child has exactly two fixed ID entries and exactly the expected complete environment block.
All unrelated entries survive byte-for-byte. Both inner and outer parent environments remain unchanged.
Receipts record counts and a block fingerprint, without recording private environment values.

The installed steam_api64.dll was read only and bound to SHA-256
71af8666392acad2080a816b9f1196fe9ccb950e1db8a549f8312c4d231f55a8.
Its preferred base is 3b400000; SteamAPI_RestartAppIfNecessary is RVA7e30.
The captured fast path loads SteamAppId at RVA1d020 and calls the imported
GetEnvironmentVariableA through RVA1c058 at call RVA7e6c with a 32-byte buffer.
The decrement/unsigned bound admits return lengths 1 through 31.
The owned replay binds the captured call target RVAa044 to an atoi callback.
A nonzero parsed value branches to RVA7e4e, clears AL and restores the native frame.
The captured SDK code thus has a false-return environment path for 311210.
This is exact-binary evidence, not a general promise about all SDK versions.

Replay.py executes the captured bytes in owned Unicorn memory only.
Owned callbacks serve GetEnvironmentVariableA, atoi and the stack probe.
The positive group passes 311210 and the 31-byte upper boundary.
The negative group stops at RVA7e87 for empty, zero-valued and 32-byte overlength input.
That stop precedes the later SDK/file/Steam-launch branches; their return value remains unknown.
No actual SDK function is called, and the installed SDK hash matches before and after.

Valve's Steamworks API overview documents that SteamAPI_Init needs a running Steam client,
the same OS user context and a license on the active Steam account. It also explains
that a true restart result relaunches the installed game through Steam.
Reference: https://partner.steamgames.com/doc/sdk/api
The child environment path above does not validate SteamAPI_Init, license admission,
or BO3's actual Steam context. Those remain a manual-test requirement.
It changes no SDK code, license checks, Steam configuration or normal files.
