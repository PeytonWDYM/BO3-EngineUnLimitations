Owned Windows SDK interception failure contract

Write the owned consumers before the helper implementation. Run memory mode first.
Physical-silent execution remains held for root's source, binary, and native-guard review.
There is no game, arbitrary executable, PID, payload, device, or profile mode.

1. The consumer calls actual CoCreateInstance, DirectSoundCreate8, and CreateThread imports.
   The helper must depend on Windows system DLLs only, with no target, consumer, game, or mod DLL dependency.
   Install all three hooks in one pre-entry transaction. Record SDK module identities and actual root calls.
   The helper must not link the unused memory report or its locale facet CRT initializers.
   Audit fixture CRT contributions as well as imported DLLs and TLS callbacks.
2. A memory-mode raw-provider baseline must expose raw leaf publications without opening physical factories.
   The baseline still commits SDK interception. It never runs an unhooked physical audio baseline.
   Every owned audio call checks the helper's committed memory-mode handshake before calling the SDK root.
   Missing or failed readiness stops before audio factory execution. Payloads remain silent even if wrapping fails.
3. Covered cold imported-DLL and startup-TLS audio calls must stop before provider work or raw publication.
   The non-returning owned stop uses TerminateProcess. No C++ exception crosses COM or loader frames.
   Earlier system dependencies precede helper attach and remain an explicit uncovered boundary.
4. Match both the already-loaded owned worker export and complete context parameter 14.
   Resolve that export without loading a DLL or waiting in the creator hook.
   Forward unmatched SDK threads unchanged, including internal SDK threads. Do not initialize their runtime.
   Preserve attributes, stack, CREATE_SUSPENDED, output ID, actual handle, priority 15, resume, native setup, and original result.
5. The matched ordinary thread entry must initialize before original TLS-like setup and first factory dispatch.
   It must not require an EXE-entry milestone. Readiness denial stops before setup or provider calls.
   Cold unmatched factory requests still stop. One owned audio caller joins before cleanup.
6. Protected memory mode must wrap known enumerator/device/client/render/session and DirectSound/base/Buffer8 chains once.
   Repeat roots, clients, buffers, callbacks, retained services, and shared/separate identities where the existing provider admits them.
   Record original HRESULTs, IIDs, actual dispatch threads, generations, first publication, and first silent output.
7. SDK provider forwarding must call saved original trampolines. It must not re-enter its own intercepted entry by mistake.
   Recognized nested audio factory requests are unsupported and must stop before a second provider call or raw publication.
   Test actual intercepted SDK re-entry in memory mode. Do not use a broad thread-local raw bypass.
   Non-audio COM requests must keep their original SDK forwarding and result.
   Runtime-ready root traces bind the immediate caller module path, base, RVA, image size and timestamp before a controlled stop.
8. Unsupported Buffer8 or initial quiet preparation must stop before native-style recovery or playback.
   WASAPI always validates the returned mix format and fills format-correct silence before SILENT ReleaseBuffer and Start.
   DirectSound independently queries and validates actual GetFormat, stops the secondary buffer, and clears its entire ring.
   Require successful full-ring Unlock before the first Play, regardless of helper wrapping.
   Later split writes also use silence. Never Restore or Play after an uncertain clear.
9. Retained callbacks, render services, session controls, and buffers must block memory-mode removal.
   Release callbacks/interfaces on their creating thread before COM uninitialization and native worker exit.
   Join the audio caller before quiescent memory runtime and hook removal.
   Physical-silent mode keeps its helper, hooks, and empty runtime resident until process exit.
   Do not claim concurrent removal or arbitrary SDK-thread quiescence from CanUnload.
10. Fixed target/consumer/helper hashes and output guards must precede child creation or compiler work.
    Reject missing/changed companions, arbitrary scenarios, repository root/child outputs, and junction aliases.
    Retain native traces, source and dependency hashes, before/after binary hashes, and exact replay commands privately.

Independent physical-silent payload contract

The owned consumer uses the actual WASAPI mix format or rejects it before output.
It admits aligned PCM8, PCM16, and IEEE float32, including validated extensible forms.
PCM8 silence is 0x80. Signed PCM and float silence are 0x00.
Every acquired WASAPI buffer is fully filled and released with AUDCLNT_BUFFERFLAGS_SILENT before Start.
There is no format override, data override, nonzero baseline, or raw output fallback.

DirectSound uses a valid hidden owned window and a stopped PCM16 secondary buffer.
It obtains actual format and caps, validates frame alignment, and locks the full ring.
It fills both returned regions with format-correct silence and verifies the complete byte total and successful Unlock.
Only then can the caller Play. Later split writes also fill both regions with silence.
Failed Lock, format, byte total, Unlock, or Stop ends that chain before any next Play.
No consumer calls Restore, volume setters, speaker setters, routing APIs, primary-buffer creation, or game APIs.

These cases validate only an owned SDK interception path.
They do not establish stock first-call chronology, every output route, driver compatibility, quiet game startup, or stability.
