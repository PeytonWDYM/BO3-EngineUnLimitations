Confirmed allocation behavior:

The engine allocates 2048 entity slots, each 1272 bytes.
The normal allocator stops at a high-water mark of 1022.
Initialization reserves the first 184 normal slots.
Separate fake entity slots start at index 1024. Sentinel slots sit between the normal and fake ranges.
When the high-water mark reaches 1022 and the reuse list is empty, the allocator calls the engine error handler.
It passes error code 2 and the text "G_Spawn: no free entities".
The error handler selects err_drop for error code 2.
This is a verified failure path. It has not been observed during Peyton's reported failure.

The allocator normally waits at least 500 milliseconds before reusing the head of its free list.
It bypasses that wait when the normal range reaches its limit.
The free routine clears a slot and records its free time.
Reserved indices below 184 do not enter the normal reuse list.
These dependencies make a single changed allocation bound an incomplete patch.
The captured stock packet writer and parser use 10-bit entity IDs, with 1023 as their terminator.
Expanding normal entities into slots 1024 and above would conflict with unpatched stock clients.

Confirmed temporary-event behavior:

The temporary-event allocator calls the normal allocator.
It stores the current server time, a temporary-event flag, and an event-derived numeric entity type.
One entity-update path checks whether the event age exceeds 300 milliseconds.
When the temporary-event flag is set, that path eventually transfers control to the free routine.
Some event types also have separate counters and allocation limits.
Their meanings and relation to War Machine grenades remain unverified.
An old event in a snapshot does not prove a leak. The server may have paused before its cleanup frame.
