Quiet audio submission boundary: scope and failure cases
2026-10-07. Written before the native fixture and implementation.

Scope
This prototype implements two Windows SDK interfaces in an owned native fixture.
The fixture sends samples to memory sinks. It never opens an audio device.
IAudioRenderClient adds AUDCLNT_BUFFERFLAGS_SILENT to every submitted packet.
IDirectSoundBuffer8 exposes separate write memory and keeps its output buffer silent.
The supported DirectSound formats are PCM8, PCM16, and IEEE float32, including valid extensible forms.
The DirectSound contract covers stopped secondary buffers without effects or outstanding raw locks.
The caller must surrender all raw buffer aliases before it exposes the wrapper.
The caller must use one Lock/Unlock pair at a time and the exact returned region sizes.
The wrapper does not implement activation, injection, device creation, or a game loader.
The fixture cannot prove game-wide silence. Other output interfaces and film routing need separate proof.

Failure cases
1. The first WASAPI packet lacks SILENT, even though later packets are quiet.
2. A caller submits nonzero data, repeated packets, eight channels, or existing flag bits.
3. An underlying GetBuffer or ReleaseBuffer error changes or a failed release destroys the pending packet.
4. QueryInterface returns a raw buffer, inconsistent IUnknown identity, or an unsupported escape interface.
5. AddRef/Release frees an object early, leaks the sink, or leaves recreated buffers unprotected.
6. A DirectSound buffer contains old nonzero samples when the wrapper first exposes Play.
7. Clearing a DirectSound buffer only at Unlock lets a playing ring read caller writes before Unlock.
8. A split Lock leaves one region audible or returns raw output memory to the caller.
9. PCM8 uses zero bytes instead of the unsigned midpoint 0x80.
10. PCM16 or float32 silence has nonzero samples, including multichannel formats.
11. Unsupported formats, malformed alignment, primary buffers, or active effects enter the quiet contract.
12. GetObjectInPath, SetFX, or QueryInterface exposes an effect or unwrapped audio buffer.
13. Wrong Unlock pointers or sizes release the raw lock or copy caller samples into the output buffer.
14. An underlying Lock, Unlock, Play, or Restore failure changes or causes an unsafe retry.
15. Restore recreates nonzero memory and Play exposes it before silence is restored.
16. A concurrent or repeated Lock overwrites the pending regions or a repeated Unlock submits stale pointers.
17. Teardown leaves an underlying lock active or fails to release the owned sink reference.
18. The fixture accidentally opens a physical device or changes endpoint/session volume.
19. The harness accepts an output directory inside the repository and creates private evidence beside public source.

Output-directory guard follow-up
Record and reproduce repository output acceptance before adding the guard.
Use one new ignored lab/evidence directory for that reproduction.
Move those outputs into the private evidence directory after the reproduction.
Reject the repository root and its subdirectories before directory creation or compiler discovery.
Verify rejection leaves new output paths absent and creates no files in existing repository paths.

Required native evidence
Run the unprotected caller-to-sink baseline before the wrapper implementation.
The baseline must fail the intended silence checks and record that expected failure.
Run the same caller paths through the wrappers after implementation.
Record first output bytes, channel counts, split regions, HRESULT values, identity, and object destruction.
Produce JSON artifacts with scenario results and explicit memory-only scope.
Do not infer BO3 launch coverage or startup silence from these artifacts.
