Write these cases before the transaction engine.

1. Apply two fixture changes together. Removal restores both exact originals.
2. Unsupported content in either target prevents every target write.
3. A running BlackOps3 process prevents apply, removal, and recovery.
4. A corrupt original backup prevents removal before any target write.
5. Already-patched content without an original backup cannot become an original.
6. Import exact originals to adopt an existing patched installation, then remove.
7. A changed target between preparation and replacement stops and rolls back owned changes.
8. A second-file replacement failure rolls back the first-file replacement.
9. A killed process after its first replacement leaves a durable journal. Recovery restores both targets.
10. Recovery refuses externally changed content and preserves the journal for inspection.
11. A target path outside its selected root fails admission.
12. A transform with an unexpected result fails before target writes.
13. Status and successful apply preserve fixture saves, settings, and unrelated files.
14. A simultaneous transaction cannot enter the same state directory.
15. A corrupt before snapshot prevents recovery before every target write.
16. Select one feature, then another. Each keeps its own exact original backup.
17. A killed process during original-backup publication must not leave a partial canonical backup.
18. A target changed during recovery must keep the journal for inspection.
19. A different state folder cannot enter while another writer holds any overlapping resolved target.
20. After actual process death, another state cannot adopt any target covered by the pending receipt.
21. Target subsets and different root sets still share target admission.
22. Death before receipt publication admits no target writes. Later recovery cannot undo another completed writer.
23. Death after the final replacement but before commit keeps every target pending.
24. Death after committed receipt publication permits another writer. Stale recovery cannot undo that writer.
25. An originals junction into an install fails before any private or target file write.
26. A redirected transaction snapshot or private file fails before recovery writes.
27. A missing receipt with admitted writes refuses recovery and keeps the journal.
28. A hardlinked private lock refuses admission without seeding an external settings file.
29. Cleanup failure after commit reports committed files. Recovery removes metadata without rolling back those files.
