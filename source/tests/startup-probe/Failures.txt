Observation-only startup probe: failures declared before implementation

Use owned native fixtures only. Do not launch BO3 or change the deployed helper.

1. Build and launcher must pin exact target/helper identities and reject private-output aliases
   before starting a child. Production accepts only the supported stock executable.
2. DllMain restores Detours imports, verifies bounded PE identity, installs one API hook on the
   current thread and publishes POD boot state. It must not wait, initialize COM or build a runtime.
   An identity/install failure refuses loading without advertising readiness.
3. Every GetStartupInfoW call reaches the original API exactly once. Preserve native output,
   last-error, calling convention and Windows exception unwinding.
4. Only the exact return site plus all 44 pinned caller bytes permit VM observation. Other DLL,
   TLS and ordinary callers forward without caller/VM reads or publication.
5. Changed caller bytes refuse observation before VM reads. Unreadable bounded globals report
   failed observations without an access violation or inferred zero state.
6. Matching calls record repeat count, thread, return address, caller bytes, raw allocator prefix,
   pool/hash and migration storage in standard-layout constinit POD. They never change native
   code, pools, capacities, codec bindings, error paths, debug registers or protected checks.
7. A publication collision does not block either caller. Count dropped writers separately.
   Readers accept only identical, even-sequence snapshots. Concurrent records must not mix fields.
8. The preimported helper is ready before owned application TLS and imported-DLL consumers.
   Their unmatched API calls preserve behavior and do not read VM globals.
9. Preserve child arguments and child-only Steam environment. Keep the reviewed stock controller
   and its bounded deadline/owned cleanup. Never grant enhanced readiness from this probe.
10. Native E2E must produce a repeatable receipt with source/profile/binary hashes, actual API
    output/error/unwind proof, coherent publication and before/after binary hashes.

11. Record the wrapper's caller only from the verified API-return-slot delta and current thread
    stack bounds, with a successful ReadProcessMemory. The owned 44-byte wrapper must prove the
    0xa0 relationship and distinguish the CRT caller from another invocation of the same wrapper.
    Missing or invalid stack evidence never establishes outside-loader or pause safety.

This is startup chronology evidence. It does not establish a safe all-thread pause or 500k activation.
