Cooperative startup gate: failures declared before implementation

Scope: owned native fixtures only. Do not launch BO3 or change the deployed helper.

1. Missing, duplicate, wrong-sized or wrong-ABI Detours payload refuses helper loading.
   The payload must bind the actual PID, creation FILETIME, primary thread and a nonzero nonce.
2. Invalid, aliased or wrongly typed child-local event/parent handles refuse before readiness.
   Parent identity and event rights must be checked. No inherited arbitrary-handle authority.
   Two different handle values for the same kernel event must also refuse before readiness.
3. DllMain only restores imports, admits the fixed image, copies POD payload, checks handles,
   installs the current-thread API detour and publishes boot. No waits, COM or VM reads there.
4. Every GetStartupInfoW call forwards exactly once with unchanged output, last-error and unwind.
   Wrong API return, caller bytes, outer CRT return or primary thread never signal or wait.
5. Loader initialization must not enter the wait, including an owned matched wrapper from TLS
   or an imported DLL. A missing loader-state admission mechanism must refuse this design.
6. Only the exact API return, 44 wrapper bytes, bounded outer CRT return and primary thread
   admit one gate generation. Repeated calls cannot reopen an already-consumed gate.
7. The ready signal follows complete POD publication of identity, nonce, generation and Waiting.
   Other threads can still run. Read observations do not prove native-world quiescence.
8. Release requires the same live parent and a valid release event while Waiting. Premature
   release, ready failure, wait failure, deadline or parent loss closes the owned child.
9. The bounded gate deadline is fixed by the admitted payload and supported range. It must not
   inherit arbitrary runtime values or change the existing production hardware-gate deadline.
10. Reuse the frozen probe observation implementation by compilation. Do not edit frozen probe,
    Control08, Steam or production 500k code. This helper writes no VM/native code or DR state.
11. Native E2E retains fixed target/helper hashes, child-only argv/Steam context, ordered gate
    phases, API/unwind evidence, loader/TLS refusals and repeatable source/build receipts.
12. A bounded native unwind must contain the verified BaseThreadInitThunk runtime-function
    range before waiting. Missing export, missing unwind range or absent frame refuses admission.
    Owned main CRT, matched EXE TLS and matched imported-DLL calls must retain their actual
    frame evidence before adding this check to the helper. No guessed stack-word scan or
    arbitrary alternate thread-entry anchor is admitted. This Windows entry anchor is not
    a published general application API contract or proof that every lock is absent.

Separate late coordinator ownership covers attach, all-thread stop, 42 edits and detach.
This gate fixture cannot establish actual BO3 loader or late-debugger compatibility.
