Late CRT VM enrollment: failures declared before implementation

Owned native E2E only. Do not launch BO3, edit the gate/coordinator or read an expanded pool
before exact-process receipt, all nineteen instructions and live helper admission succeed.

1. Neither exact FILETIME-PID receipt exists: preserve stock capacity. Stale filenames do not enroll.
2. Both legacy .json and -late.json receipts exist for the process: refuse ambiguity before reads.
   An invalid late receipt cannot fall back to a valid legacy receipt or stock enrollment.
3. Late receipt requires exact schema/candidate/startupMethod/PID/FILETIME/image/helper identity,
   totals 500001/65000, roots 18/8, migration bytes 33554432 and exactly 42 edits.
4. Require attached, committed, detached, debuggerAbsent and released true. Require terminated
   and rollbackCompleted false, debugRegisterWrites integer zero and liveAllocationValidated false.
   Reject missing fields, wrong types, partial phases, malformed JSON and oversized receipts.
5. The late route must use the deployed original VM helper identity 09b947... for real BO3.
   Owned fixtures may use only their private exact helper hash and fixed capacity inventory.
6. Every patched count instruction, loader-ready Boot24 and StateBindings48 must match live memory.
   A stock, partial, unreadable, wrong-opcode or wrong-bindings runtime refuses before pool reads.
7. A valid late receipt with liveAllocationValidated false can authorize the existing sampler only
   after independent live runtime proof. It does not establish game or gameplay validation.
8. Receipt content or route changes, a second route appearing, changed code/bindings or child exit
   must refuse during enrollment and repeated code verification. Preserve process-handle binding.
9. The existing legacy receipt route, normalized code hashes and stock profile capacities remain
   supported. No profile-only capacity edit or serialized receipt grants expanded read authority.
10. The owned E2E must retain exact process identity, read sizes, sampled counts, source/binary
    hashes, refusal reasons and a repeatable receipt. Refusals perform no expanded pool read.
11. Late metadata requires fixed generation one, positive DWORD primary/attach/write-event
    thread IDs, and matching attach/write-event IDs. Gate base, attach breakpoint and attach
    thread entry must be positive bounded native addresses. Observed thread count must be
    bounded and at least two. Corrupt or missing metadata refuses before expanded reads.
