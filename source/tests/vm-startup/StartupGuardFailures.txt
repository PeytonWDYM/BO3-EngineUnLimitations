Startup guard capture audit: failure cases declared before the harness

1. Refuse a dump whose PID, creation time, executable hash, module base, size or timestamp does not match process.json.
2. Refuse two references to the same process instance as independent startup evidence.
3. Refuse missing or partial bytes in the 195-byte code range.
4. Refuse different startup bytes or any mature/startup difference beyond byte zero.
5. Require startup byte 40 and mature byte C3 with their complete recorded range hashes.
6. Require both startup captures to retain zero server pool and hash pointers.
7. Require complete instruction coverage and a PUSH RBX startup instruction at the native function entry.
8. Require the original RUNTIME_FUNCTION boundary and identical native unwind records across the captures.
9. Compare every inventory guard and count instruction. Do not accept an alternate hash or omit a guard.
10. Preserve every inventory field except the single proven hash correction.
11. Record dump/process identities, full range bytes, hashes, disassembly and unwind evidence in a repeatable private artifact.
12. Treat a mature RET as observed runtime modification. Name its writer only if a captured write site proves provenance.

The audit reads saved captures only. It does not launch a game, deploy a patch or change protected startup behavior.
